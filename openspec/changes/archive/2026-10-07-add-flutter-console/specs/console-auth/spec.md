## Purpose

控制台可视化后，平台 API 从"内部 curl 工具"变为暴露面，需最小可用认证：单用户令牌登录 + API 过滤器校验。仍属 design D10 声明的安全边界内的过渡实现（服务器化前升级为多用户与凭据治理）。

## ADDED Requirements

### Requirement: 令牌登录
系统 SHALL 提供登录端点：提交令牌字符串，与配置的平台令牌匹配则返回认证成功标记（会话有效期），不匹配返回明确拒绝。平台令牌经配置项设定，未配置时认证功能整体关闭（零鉴权兼容模式，保持既有 curl 用法不变）。

#### Scenario: 登录成功
- **WHEN** 用户提交与配置一致的令牌
- **THEN** 返回会话标记，后续请求携带该标记被放行

#### Scenario: 登录拒绝
- **WHEN** 用户提交错误令牌
- **THEN** 返回拒绝响应与可读错误消息，不暴露令牌内容

### Requirement: API 访问控制
启用认证时，除白名单路径（登录端点、静态控制台资源）外，所有 API 请求 SHALL 携带有效会话标记；缺失或无效时返回未认证响应（前端据此跳转登录页）。认证关闭时所有请求直接放行。

#### Scenario: 无令牌访问受保护 API
- **WHEN** 认证启用且请求未携带会话标记访问业务 API
- **THEN** 返回未认证状态码，响应体不含业务数据

#### Scenario: 白名单放行
- **WHEN** 认证启用且请求访问登录端点或控制台静态资源
- **THEN** 请求不经令牌校验直接放行

#### Scenario: 兼容模式
- **WHEN** 平台令牌配置为空
- **THEN** 全部 API 无需令牌即可访问（与 MVP 行为一致）
